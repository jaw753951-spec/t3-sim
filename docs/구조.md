# 구조

`intern_sim.html` 은 **결과물**이다. 직접 고치지 않는다.
고칠 곳은 `src/` 아래이고, `node build.js` 가 한 장으로 이어 붙인다.

```
node build.js           src/ → intern_sim.html
node build.js --check   뽑지 않고 순서·중복·문법만 본다
node sim_check.js A B   두 결과물의 동작을 견준다 (다르면 0 아닌 값으로 끝난다)
```

## 층

번호가 곧 적재 순서다. 앞의 층은 뒤의 층을 모른다.

| 층 | 무엇이 | 규칙 |
|---|---|---|
| `10-config` | **수치** — R · SR · 증상표 · 레벨표 · 저울 | 숫자만. 함수도 화면도 없다 |
| `20-data`   | **데이터** — 카드 22장 · 덱 · 카드팩 · 환자 대본 23명 · 보스 | 내용물. 규칙이 아니다 |
| `30-core`   | **로직** — 커널 · 생성기 · 카드 · 환자 · 세션 · 스토리 | 화면을 한 번도 안 쓴다 |
| `40-ai`     | **자동 진행** — 빔 탐색(기본) · v18 휴리스틱(대조용) | 〃 |
| `50-wire`   | **배선** — `K` `L` `C` `P` `D` `H` | 원본이 require 로 나눠져 있던 자리 |
| `60-text`   | **문안** — 키워드·박자·덮어쓰기 칸 설명문 | 사람이 읽는 글. 여기부터 화면이다 |
| `70-ui`     | **화면** — 전역 · 툴팁 · 카드 · 판 · 손 · 모드 다섯 | |
| `80-tools`  | **도구** — 규칙 덮어쓰기 · 배치 · 환자 만들기 | 밸런싱용. 게임 규칙이 아니다 |
| `90-boot`   | **부팅** | 반드시 마지막 |

`00-shell` 은 JS 가 아니다 — `head.html` · `style.css` · `body.html` 세 장이
결과물의 껍데기가 된다.

### 왜 이 순서인가

`const` 는 끌어올려지지 않는다 (TDZ). 값이 값을 참조하면 **순서가 곧 규칙**이다.
지금 걸려 있는 것:

- `SR.DIS_BASE` 가 `LVTAB` 을 읽는다 → `story-rules.js` 는 `symptoms.js` 뒤
- `ALLSYM` ← `SYM` · `ONE_DECK` ← `DECK_D2` · `PRESETS` ← 덱들
- `PACKS` ← `BASE10`/`DEPT6` · `STORY_DECK` ← `packDeck(PACKS, SWAP)` — 표가 먼저, 편성이 나중
- `R0`/`SR0` ← `R`/`SR` · `AIW` ← `AIW_DEF` · `rank` ← `TIER`
- `SESSIONS` 펼치기와 `BOSS` 펼치기는 각자의 표 바로 뒤에서 돈다

함수 선언은 끌어올려지므로 층을 넘어 불러도 된다.
`build.js` 는 `src/` 에 있는데 `ORDER` 에 없는 `.js` 를 잡아낸다 — 조용히 빠지지 않는다.

## 자름 앵커

`10-config` ~ `50-wire` 는 화면을 쓰지 않는다. `sim_check.js` 가 이 구간만 떼어
node 에서 돌린다. 경계 앵커는 **`build.js` 가 찍는다** — `src/` 안에서 찾지 않는다.

```
//@ 자름.커널시작   10-config 앞
//@ 자름.커널끝     40-ai 뒤
//@ 자름.배선시작   50-wire 앞
//@ 자름.배선끝     60-text 앞
```

파일마다 `//@ 파일.<층>/<이름>` 앵커도 찍힌다. 결과물에서 어느 소스로
돌아가야 하는지 그 줄이 알려 준다.

# 3단계 — 하드코딩을 변수로

## 카드 한 장의 숫자는 한 곳에만 적는다

전에는 같은 숫자가 세 군데에 박혀 있었다 — 메타 필드 `sup:5` · 본문 `'억제 −5'` ·
`fx` 안의 리터럴 `5`. 하나만 고치면 나머지 둘이 거짓말을 했다.

```js
'감초 탕약': {cost:1, dept:'내과', verb:'억제', target:'node', v:{sup:6},
  text:'억제 −{sup}',
  fx:(S,n,a,v)=>K.suppress(S,n,v.sup)},
```

| 자리 | 무엇 |
|---|---|
| `v`      | 이 카드의 숫자. **여기가 유일한 자리다.** 값이 함수면 판을 넣어 부른다 — 규칙 덮어쓰기가 `R` 을 바꾸면 카드에 적힌 숫자도 따라 바뀐다 |
| `text`   | 본문. `{sup}` 처럼 `v` 의 열쇠를 감싸면 화면이 그 자리에 숫자를 넣는다 |
| `fx`     | 실제 효과. 네 번째 인자로 `v` 를 받는다. 리터럴을 적지 않는다 |
| `raw`    | 이 카드가 지금 이 자리에 넣는 억제 원값. 안 적으면 `v.sup` |
| `live`   | 본문의 이 열쇠는 '적힌 수' 가 아니라 '지금 실제로 들어가는 수' 를 보인다 |
| `branch` | 대상에 따라 갈리는 카드. 지금 걸리는 쪽만 물들고 나머지는 흐려진다 |

## 슬더스식 수치 표시

카드에 적힌 숫자를 **지금 이 판 이 자리에서 실제로 일어나는 값**으로 그린다.
적힌 값보다 세지면 초록(`.vup`), 약해지면 빨강(`.vdn`).
코스트만 반대다 — 싸지는 것이 좋은 일이라 낮아질 때 초록이다.
갈래가 안 걸리는 쪽은 흐려진다(`.voff`). 물든 숫자에 마우스를 올리면
적힌 값 · 지금 값 · 왜 그렇게 되었는지가 뜬다.

예 — 불안 · 기세 3 · 보호막 30% · 탈수 하나 · 관해 중, 통증 자리를 고른 상태:

| 카드 | 적힌 값 | 보이는 값 | 왜 |
|---|---|---|---|
| 감초 탕약   | −6 | **−4** 빨강 | 불안 −1 → 5, 보호막 ⌈5×0.7⌉ = 4 |
| 몰아붙인다  | −4 | **−15** 초록 | 기세 3 → 4+18 = 22, 불안 −1 → 21, 보호막 ⌈21×0.7⌉ = 15 |
| 수액 투여   | 5  | **2.5** 빨강 | 탈수 ÷2 |
| 지혈 압박   | −3 / −6 | **−2** 빨강 · 6 흐림 | 대상이 출혈이 아니라 낮은 쪽. 불안 −1 → 2 |
| 관해 유도   | 2  | **0** 초록 | 관해 중에는 공짜 |
| 환기하세요  | +2 | +2 무색 | 관해 +1 과 불안 −1 이 맞물려 제자리 |

**거짓말하지 않는 구조.** 실제 값은 커널의 `supAmt` · `stabAmt` · `diagAmt` 가 낸다.
`suppress` · `stabilize` · `diagnose` 가 정산할 때 부르는 함수와 **같은 것**이다.
이 파일에서 이미 쓰던 원칙(`growAmt` — 예고와 정산이 같은 함수)을 셋으로 넓혔다.
표시용 계산을 따로 짜면 언젠가 갈라지고, 갈라지면 카드가 거짓말을 한다.

### 겸사겸사 고친 것

- **S 산식이 두 번 적혀 있었다.** `S_of` 와 `medianBoards` 가 같은 식을 따로 들고
  있어서 한쪽만 고치면 검산이 검산 구실을 못 했다. `sFormula` 하나로 합쳤다.
- **중앙값 검산의 `+7.5` 가 초기값 폭 `16` 과 따로 놀았다.** 이제 `INIT_MID` 가
  `INIT_SPREAD` 에서 나온다. 폭을 바꾸면 검산이 따라온다.
- `valDiv` 는 나누는 수로 뒀다. `1/25` 를 곱셈으로 바꾸면 이진수로 안 떨어져
  S 가 미세하게 흔들리고 `lv_of` 경계에서 레벨이 튄다.

### 일부러 안 건드린 숫자

밸런싱 손잡이가 아니라 알고리즘의 일부인 것들.

- `mulberry32` 의 계수 — 난수 알고리즘. 바꾸면 같은 씨앗이 다른 판을 뱉는다
- `for(let t=0;t<600;t++)` · `guard++<40` 따위 — 루프 가드. 게임 수치가 아니다
- `evo:99` — '진화 안 함' 표식
- `clone` 의 `rng:()=>0.5` — 탐색 중 난수 고정

## 확인

기준본 대비 **판이 다르게 돈 곳 0** — 생성 15 · 단판 20(양쪽 AI) · 세션 4 ·
스토리 9 · 레벨표 검산까지 전부 그대로다. 손잡이가 늘고 준 것만 다르다.

# 4단계 — 설명문이 거짓말하지 않게

## 무엇이 문제였나

「규칙 덮어쓰기」로 만질 수 있는 손잡이의 값이 **설명문에 글자로 박혀 있었다.**
그래서 밸런싱하려고 값을 만지는 순간 툴팁이 거짓말을 시작했다.
이 도구의 용도가 정확히 "값을 만져 보는 것"이므로, 늘 틀린 설명을 읽게 된다.

실측 — `ATK_K` 0.20→0.50, `DEHY_STAB` 2→4, `PAIN_FLOOR` 0.25→0.10,
`EVO_BLEED_ACC` 2→3 으로 덮어쓴 뒤:

| 설명문이 말한 것 | 실제 |
|---|---|
| 탈수 — "이 수로 나눈다. **2면 절반이다**" | 4로 나눠 1/4 |
| 발열 — "수치의 **20%**를 쓴다" | 50% |
| 통증 — "하한은 규칙값(**현재 25%**)" | 10% |
| 출혈 — "진화하면 **두 배**가 된다" | 세 배 |
| 보호막 — "탈수가 있으면 안정화 효율이 **절반**" | 1/4 |

`SYMPARAM.why` 만이 아니라 `KWTIP` · `LINKTIP` · `BEATTIP` · `UNIQTIP` ·
`SYMTIP` 전체가 같은 병이었다.

## 어떻게 고쳤나

규칙값을 인용하는 항목을 전부 **`get` 접근자**로 바꿨다. 읽을 때마다 지금의
`R` · `SR` · `CARDS` 를 본다.

```js
get '관해도'(){ return TT('관해도 · 내과',
  `관해를 유지하는 자원. 상한 <b>${R.REM_MAX}</b>, 개시 시 초기값 <b>${R.REM_START}</b>.…`) },
```

**소비처는 한 줄도 안 고쳤다.** `KWTIP['관해도']` 로 꺼내면 예전처럼 문자열이
나오고, 문자열 이어붙이기(`KWTIP['재진'] + '…'`)도 그대로 돈다.
규칙과 무관한 순수 설명은 그냥 문자열로 뒀다.

`SYMPARAM` 은 층으로도 갈랐다.

| 어디 | 무엇 |
|---|---|
| `10-config/symptoms.js` · `SYMPARAM` | `key` · `def` 만. `sp()` 가 쓰는 것 |
| `60-text/keywords.js` · `SYMDOC` | `label` · `step` · `why`. 사람이 읽는 몫 |

**커널 절단 구간 안의 HTML 태그가 0 이 됐다.** 그 구간의 계약은 "화면을 한 번도
쓰지 않는다" 인데 `<b>`·`<br>` 뭉치가 들어앉아 있었다.

## 다시 생기지 않게

`ui_check.js` 가 **손잡이를 전부 흔들어 놓고 안 움직이는 설명문을 찾는다.**
`R` · `SR` 의 모든 숫자를 `v*3+1` 로 덮어쓴 뒤 사전 51개 항목을 견준다.
움직이지 않아도 되는 13개(규칙값을 인용하지 않는 순수 설명)는 목록에 적어 뒀다.
**목록에 없는 이름이 걸리면 그 설명문에 숫자를 박은 것이다.**

지금 상태 — 따라오는 설명문 38, 안 따라오는 것 0.

## 검산을 진짜 검사로

`medianBoards` 는 "레벨표가 스스로와 아귀가 맞는가" 를 재는 자체 검산인데,
**아무도 그 결과를 보지 않았다.** 화면에도 안 뜨고 단언도 없었다.
죽은 코드가 아니라 한 번도 켜진 적 없는 안전장치였다.

`sim_check.js` 에 불변 조건 넷을 세웠다. 견주기(`A ≡ B`)는 '달라졌다' 만 잡는다.
처음부터 어긋나 있거나 양쪽이 똑같이 어긋나 있으면 못 잡는다. 그것을 여기서 잡는다.

| 무엇 | 언제 걸리나 |
|---|---|
| 레벨표 중앙값이 그 레벨로 되돌아오는가 | `LVTAB` 이나 `SW`(산식 계수·레벨 경계)를 만졌을 때 |
| 카드 본문의 `{열쇠}` 가 그 카드 `v` 에 있는가 | 서식을 오타 냈을 때 |
| 덱·가방 풀의 이름이 실재하는 카드인가 | 카드 이름을 고치고 덱을 안 고쳤을 때 |
| 대본 환자의 증상이 증상표에 있는가 | 증상 이름을 고쳤을 때 |

불변 조건은 **시나리오보다 먼저** 돈다. 데이터가 어긋나 있으면 시나리오는
엉뚱한 곳에서 스택 트레이스로 터진다 — 그 전에 무엇이 어긋났는지 이름으로 말해 준다.

일부러 깨뜨려 넷 다 걸리는 것을 확인했다.

> 검사기 자체에도 버그가 있었다. 불변 조건 덩어리가 통째로 템플릿 리터럴이라
> 정규식의 `\w` 를 템플릿이 `w` 로 삼켜 카드 본문 검사가 아무것도 안 걸렸다.
> 백슬래시를 둘로 적어 고쳤고, 줄이지 말라는 주석을 달아 뒀다.

## 이번에 더 올린 손잡이

`R.EVO_X2`(진화 배수 — 감염·호흡곤란) · `R.EVO_INF_DIAG` · `R.DRAW_CUT` ·
`SR.BEAT_CLOCK` · `SR.BEAT_EVO_PULL` · `SR.BEAT_SCRATCH_N`.

진화 두 배가 세 군데에 있었는데 출혈만 손잡이가 있고 감염·호흡곤란은 생 리터럴이었다.
`bosses.js` 의 분화 초기값(`35 + rng()*25`)이 `SR.DUP_BASE`/`DUP_SPREAD` 와
같은 값을 따로 들고 있던 것도 합쳤다.

# 5단계 — 자리에도 같은 색, 검사에도 같은 잣대

## 자리의 처치선을 물들인다

카드에서 하던 것을 자리에도 붙였다. **처치선은 늘 보이는 표식**이다 —
뱃지(강반응·약반응·휴면)는 이미 끊을 수 있을 때만 뜨는데, 정작 이 수가 궁금한 것은
아직 못 끊을 때다.

```
선 35/89     ← 규칙상 44(초기값의 50%)여야 할 것이 35다. 빨강.
```

무엇이 움직이는가 — **약화가 올리고(끊기 쉬워진다) 통증이 내린다.**
바탕값은 규칙이 정한 몫(`R.KILL_LINE`, 병 노드는 `R.DIS_KILL_LINE`)이고,
지금 값은 커널의 `killLine` 이 낸다. 화면이 따로 계산하지 않는다.

색 규칙은 카드와 **같은 함수**(`driftSpan`)를 쓴다. 두 벌이면 같은 판을 보고
카드와 자리가 서로 다른 말을 하게 된다. 방향만 부르는 쪽이 정한다 —
코스트는 낮아지는 쪽이, 처치선은 높아지는 쪽이 좋은 일이다.

| 상황 | 선 | 색 |
|---|---|---|
| 그냥 (초기값 54) | 27 | 무색 |
| 약화 2 | 32 | 초록 |
| 통증 한 자리 | 13 | 빨강 |
| 약화 4 + 통증 | 24 | 빨강 — 약화로 올려도 바탕값 27 에는 못 미친다 |

## 태그 칸도 표에서 만든다

`tagbox` · `tagnote` 는 JS 도 CSS 도 안 쓰는 id 였다. 지우려다 보니 그 안이
같은 병이었다 — 마크업에 태그 **일곱 개**를 손으로 적어 뒀는데 `HP_TAG` 에는
열한 개가 있고 「환자 만들기」는 열한 개를 다 보여 주고 있었다. 두 화면이
서로 다른 목록을 내놓던 셈이다. 아래 설명도 `TAG_CAP` · `TAG_GROUP` 을 글로
베껴 놔서 상한이나 묶음을 고치면 곧바로 거짓말이 됐다.

지워야 할 id 가 아니라 채워야 할 자리였다. `renderTagBox()` 가 표에서 만든다.
(`ovrbox` 는 정말로 쓰는 데가 없어 뺐다.)

## 렌더 함수에 남아 있던 숫자

4단계의 훑기는 **설명 사전**만 봤다. 화면을 찍어 보니 자리 렌더 함수 안에
같은 병이 더 있었다 — 보호막 툴팁의 "탈수가 있으면 안정화 효율이 **절반**",
처치선 툴팁의 "약화 한 스택이 **2.5%p**", "초기값 **50%** 에서 캡한 뒤 **1/3**",
설치물의 "**−rig×2**", 병 노드의 "받는 피해가 **절반**". 전부 손잡이를 읽게 고쳤다.

## 깊은 경로 검사 다섯

화면 글자를 견주는 것만으로는 "눌렀더니 엉뚱한 일이 일어난다" 를 못 잡는다.
`ui_check.js` 가 한 파일 안에서 스스로 앞뒤가 맞는지 본다.

| 무엇 | 무엇을 재는가 |
|---|---|
| 되돌리기 | 카드를 내고 무르면 판이 그대로 돌아오는가 |
| 사혈 | 지불액이 `R.BLEED_PAY` 그대로인가 |
| 설치물 | 카드값대로 놓이고, 개방하면 사라지며 수치가 주는가 |
| 처치 | 처치선 아래면 끊기고 광역 억제가 도는가 |
| 규칙 덮어쓰기 | 걸고 풀면 제자리로 오는가 |

셋 다 일부러 깨뜨려 잡히는 것을 확인했다.

> 사혈 검사가 처음에는 헛돌았다. 예상값을 `bleedPay()` 로 구했더니 그 함수를
> 망가뜨려도 예상값이 같이 망가져 둘이 계속 일치했다. **검사가 검사 대상을
> 기준으로 삼으면 안 된다** — 규칙값(`R.BLEED_PAY`)에서 따로 세도록 고쳤다.

## 검사 도구 한눈에

```
node build.js --check                          순서 · 중복 · 문법
node sim_check.js A.html B.html                판이 다르게 도는가 + 불변 조건 넷
node ui_check.js  A.html B.html                화면 글자 + 깊은 경로 다섯 + 설명문 추적
```

`sim_check` 의 불변 조건과 `ui_check` 의 깊은 경로·설명문 추적은 **견주기와 별개**로
그 파일 하나만 놓고도 맞아야 하는 것들이다. 견주기는 '달라졌다' 만 잡는다.

# 6단계 — 스토리 가방을 팩으로 짠다

## 무엇이 바뀌었나

스토리 가방은 **낱장이 아니라 팩**으로 짠다. 무엇을 몇 장 넣을까가 아니라
어느 팩을 들일까가 판단이다. 팩 하나가 통째로 들어오고 통째로 나간다.

| 카드팩 | 몇 장 | 비고 |
|---|---|---|
| 기본 카드팩 | 10 (`BASE10`) | `fixed` — 늘 든다, 뺄 수 없다 |
| 외과 · 내과 · 의공학 보급 카드팩 | 각 2 | `group:'supply'` — **셋 중 하나만 든다** |
| 정착지 의사 카드팩 | 3 | 빌려온 물건 · 손이 기억한다 · 매듭 짓다 |

10 + 2 + 3 = **15**. 스토리 가방 상한(`STORY_CAP`)과 딱 맞는다.
보급을 한 팩으로 묶어 여섯 장을 다 주면 19장이 되어 상한을 넘는다 —
분과를 셋으로 쪼개고 묶음으로 둔 이유가 그것이다. 어느 분과를 손에 쥘지가
방침 선택과 붙는 판단이 된다.

**묶음 규칙은 `packPick` 한 곳에만 있다.** 묶음 팩은 고르면 같은 묶음의
나머지가 빠지고, 고른 팩을 다시 눌러도 빠지지 않는다 — 묶음에서는 하나를
반드시 든다. 묶음이 아닌 팩(정착지 의사)은 눌러서 넣고 뺀다.

## 대체 카드 풀

한 자리에 놓을 수 있는 카드가 여럿인 자리가 있다. **바꾸는 것이지 더하는
것이 아니다** — 자리 수는 늘지 않으므로 상한도 흔들리지 않는다.

| 자리 (팩에 적힌 기본) | 대신 놓을 수 있는 카드 |
|---|---|
| 감초 탕약 | 그물 |
| 도와드릴까요? | 곗날 |
| 매듭 짓다 | 눈 딱 감고 |

카드 밑에 **레터박스**가 붙고, 그 자리에 놓을 수 있는 카드가 몇 장인지를
숫자로 보인다. 지금은 **0 아니면 2**다. 카드를 누르면 그 자리 옆에 대체 카드
풀이 펼쳐지고 나머지 화면은 페이드 아웃된다 — 0인 자리도 눌린다. 없다는
것을 그 자리에서 보여야 "이 카드는 왜 안 되지" 를 묻지 않는다.

## 어디에 적혀 있나

두 표가 전부다. 팩을 더하려면 `PACKS` 에 한 줄, 자리를 늘리려면 `SWAP` 에 한 줄.

```js
const PACKS = [
  {id:'base', name:'기본 카드팩', fixed:true, cards:BASE10},
  {id:'surg', name:'외과 보급 카드팩', group:'supply', cards:SUPPLY.외과},
  … ];
const SWAP  = [ ['감초 탕약','그물'], … ];          // 첫 장이 팩에 적힌 기본
```

| 이름 | 어디 | 무엇 |
|---|---|---|
| `SUPPLY` | `20-data/decks.js` | 분과마다 두 장. `DEPT6`(왕진 풀)도 여기서 나온다 |
| `PACKS` · `SWAP` · `PACK_GROUP` | 〃 | 표. 팩과 자리와 묶음 이름을 정하는 유일한 자리 |
| `swapPool(id)` · `packDeck(on, swap)` · `packPick(on, id)` | 〃 | 표를 읽는 잔손. 가방 한 벌과 묶음 규칙은 여기서만 나온다 |
| `STORY_PACKS` · `STORY_SWAP` | 〃 | 지금 편성. `STORY_DECK` 은 이 둘의 **결과**다 |
| `openPackStory` 외 | `70-ui/pack-ui.js` | 편성 화면. 표를 그릴 뿐 규칙을 갖지 않는다 |

낱장 편성(`70-ui/deck-ui.js` 의 `openDeck`)은 단판·세션이 그대로 쓴다.
스토리만 팩으로 갈아탔다 — `openDeckStory` 와 `POOL.story` 는 부르는 곳이
없어져 걷어냈다.

## 화면

자리 하나 = **카드 한 장 + 그 밑의 레터박스**. 페이드 아웃은 `.fade` 한 장이
화면을 덮고 열린 자리(`.slot.on`)만 그 위로 올라오는 식이다 — 카드마다 색을
따로 흐리지 않는다.

대체 풀 판은 **툴팁과 같은 식으로 놓는다**(`pkPlace`). 기준이 화면이라 판은
`fixed` 이고, 자리 오른쪽에 붙이되 오른쪽으로 넘칠 때만 왼쪽으로, 아래로
넘칠 때만 위로 물린다. 그래도 화면보다 길면 판 안에서 구른다. 전에는
자리에 붙여 놓기만 해서 **아래쪽 팩(정착지 의사)에서 열면 밑이 잘렸다.**

화면에 글을 두지 않는다. 팩 이름과 장수, 레터박스의 숫자, 손잡이 이름이면
읽을 것이 다 있다 — 팩이 무엇인지 설명하는 문단과 팩마다 붙어 있던 한 줄
소개는 걷어냈다.

묶음은 머리 한 줄(`PACK_GROUP`)을 달고 한 칸(`.group`)에 모아 그린다.
고른 팩에는 뺄 손잡이가 없고 「골랐다」만 뜬다 — 넣고 빼는 것이 아니라
고르는 것이라는 게 손잡이 모양에서 보여야 한다.

편성은 **확정해야 판에 얹힌다.** 「이 가방으로 간다」를 누르기 전까지
`STORY_DECK` 은 움직이지 않는다 — 가방 화면에서 만지작거린 것이 진행 중인
판에 새지 않게.

## 검사
