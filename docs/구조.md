# 구조

`intern_sim.html` 은 **결과물**이다. 직접 고치지 않는다.
고칠 곳은 `src/` 아래이고, `node build.js` 가 한 장으로 이어 붙인다.

```
node build.js           src/ → intern_sim.html
node build.js --check   뽑지 않고 순서·중복·문법만 본다
node sim_check.js A B   두 결과물의 동작을 견준다 (다르면 0 아닌 값으로 끝난다)
```

## 층

번호가 곧 적재 순서다. 앞의 층은 뒤의 층을 모른다.

| 층 | 무엇이 | 규칙 |
|---|---|---|
| `10-config` | **수치** — R · SR · 증상표 · 레벨표 · 저울 | 숫자만. 함수도 화면도 없다 |
| `20-data`   | **데이터** — 카드 22장 · 덱 · 환자 대본 23명 · 보스 | 내용물. 규칙이 아니다 |
| `30-core`   | **로직** — 커널 · 생성기 · 카드 · 환자 · 세션 · 스토리 | 화면을 한 번도 안 쓴다 |
| `40-ai`     | **자동 진행** — 빔 탐색(기본) · v18 휴리스틱(대조용) | 〃 |
| `50-wire`   | **배선** — `K` `L` `C` `P` `D` `H` | 원본이 require 로 나눠져 있던 자리 |
| `60-text`   | **문안** — 키워드·박자·덮어쓰기 칸 설명문 | 사람이 읽는 글. 여기부터 화면이다 |
| `70-ui`     | **화면** — 전역 · 툴팁 · 카드 · 판 · 손 · 모드 다섯 | |
| `80-tools`  | **도구** — 규칙 덮어쓰기 · 배치 · 환자 만들기 | 밸런싱용. 게임 규칙이 아니다 |
| `90-boot`   | **부팅** | 반드시 마지막 |

`00-shell` 은 JS 가 아니다 — `head.html` · `style.css` · `body.html` 세 장이
결과물의 껍데기가 된다.

### 왜 이 순서인가

`const` 는 끌어올려지지 않는다 (TDZ). 값이 값을 참조하면 **순서가 곧 규칙**이다.
지금 걸려 있는 것:

- `SR.DIS_BASE` 가 `LVTAB` 을 읽는다 → `story-rules.js` 는 `symptoms.js` 뒤
- `ALLSYM` ← `SYM` · `BAG_D3`/`ONE_DECK`/`STORY_DECK` ← `DECK_D2` · `PRESETS` ← 덱들
- `R0`/`SR0` ← `R`/`SR` · `AIW` ← `AIW_DEF` · `rank` ← `TIER`
- `SESSIONS` 펼치기와 `BOSS` 펼치기는 각자의 표 바로 뒤에서 돈다

함수 선언은 끌어올려지므로 층을 넘어 불러도 된다.
`build.js` 는 `src/` 에 있는데 `ORDER` 에 없는 `.js` 를 잡아낸다 — 조용히 빠지지 않는다.

## 자름 앵커

`10-config` ~ `50-wire` 는 화면을 쓰지 않는다. `sim_check.js` 가 이 구간만 떼어
node 에서 돌린다. 경계 앵커는 **`build.js` 가 찍는다** — `src/` 안에서 찾지 않는다.

```
//@ 자름.커널시작   10-config 앞
//@ 자름.커널끝     40-ai 뒤
//@ 자름.배선시작   50-wire 앞
//@ 자름.배선끝     60-text 앞
```

파일마다 `//@ 파일.<층>/<이름>` 앵커도 찍힌다. 결과물에서 어느 소스로
돌아가야 하는지 그 줄이 알려 준다.

## 옮기기 전 구조

원본은 한 파일 4,429줄 · 아홉 절(`§1`~`§9`)이었다. 절과 층의 대응:

| 옛 | 새 |
|---|---|
| §1 규칙 커널 | `10-config/rules.js` + `30-core/kernel.js` |
| §2 레벨 생성기 | `10-config/levels.js` + `30-core/generator.js` |
| §3 카드 | `20-data/cards.js` + `20-data/decks.js` + `30-core/card-rules.js` |
| §4 대본 환자 | `20-data/patients.js` + `30-core/patients.js` |
| §5 세션 | `10-config/session.js` + `30-core/session.js` |
| §6 스토리 3막 | `10-config/story-rules.js` + `20-data/bosses.js` + `30-core/story.js` |
| §7 자동(옛) | `40-ai/heuristic.js` |
| §8 자동(새) | `10-config/ai-weights.js` + `40-ai/beam.js` |
| §9 화면·배치 | `60-text/*` + `70-ui/*` + `80-tools/*` + `90-boot.js` |

절이 층 둘로 갈린 자리가 이번 개편의 요점이다 — **수치·데이터·문안이
로직에서 떨어져 나왔다.**

## 이번 개편에서 확인한 것

`reference/intern_sim_v25.html` 이 기준본이다. 옮긴 뒤 두 가지로 확인했다.

- **줄 단위** — 원본 JS 유효줄과 결과물 JS 유효줄을 다중집합으로 비교.
  없어진 코드 0줄, 늘어난 코드 0줄. 차이는 전부 옛 `§` 배너(이 문서로 옮김)와
  `build.js` 가 새로 찍은 머리말뿐이다.
- **동작** — `sim_check.js` 로 판 생성 15판 · 레벨표 검산 · 단판 20판(새·옛 AI 둘 다) ·
  세션 3일차 · 스토리 보스×방침 · 손잡이 전량을 견주어 전부 일치.
- **화면** — headless Chromium 으로 두 파일에 같은 조작(고정 씨앗 새 판 → 자동 3턴 →
  자동 완주 → 탭 다섯 → 스토리·세션·만들기·덮어쓰기 판 → 툴팁 등록 수)을 넣어
  화면 글자 전량 일치. 양쪽 다 콘솔 오류 0.

**코드 내용은 한 줄도 바뀌지 않았다.** 옮기기만 했다.
